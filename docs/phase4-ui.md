# Phase 4 UI: the example workflow's windows, shortcuts and NPCs

Batt, 2026-10-07:
- **YOLO is ONLY for the game world:** monsters, NPCs, ground items.
- **The UI is fixed pixels, with no training:**
  - menus by KEYBOARD SHORTCUT;
  - inside windows, anchors and templates;
  - text through the locale-pack keys (ADR-0011/0012);
  - NPC dialogs from rAthena's scripts (static data, ADR-0015). The bot knows the expected
    options, reads the text on screen, and clicks the match.
- **The multimodal reasoning happens ONCE, at design time.** The bot runs the rule. An LLM never
  decides a click at run time, and in-game text is data, never instructions.
- **Every rule is proven ALONE first** (`demonstrations.md`).
- **The knowledge layers:** L1 concepts (`knowledge/README.md`), with L2 client / L3 server / L4
  locale bindings (`packages/poring_skills`).

## The route: Novice → Merchant → Blacksmith (pre-renewal, lab rAthena)
The detail (NPC positions, menu options, quiz answers, EXP projections) is GPL-derived and stays
local. It is generated by `scripts/kb_route.py` and `scripts/kb_bindings.py` into
`data/kb/route.md` and `data/kb/bindings/lab-rathena.json`. Only the structure is here:

1. **Novice.**
   - The character starts in the novice training grounds; its receptionist offers the training
     or direct access to the world.
   - The goal: Job Level 10 with Basic Skill at 9.
   - Basic Skill also gates sitting (level 3) and storage (level 6).
   - Leveling candidates: the Prontera fields' weakest spawns (the projection: ~1,150 job EXP).
2. **Merchant job change, Alberta.** The Merchant guild's chief, then:
   - a fee;
   - a delivery to one of four random destinations, with a serial number to type;
   - the storehouse staff;
   - the return.
   It takes several NPCs, menus and one number input.
3. **Merchant leveling to Job Level 40.** Every skill point must be spent before the second job.
   - The candidate fields around Prontera / Payon / Geffen are tabled locally, by level, EXP and
     aggression.
   - The Merchant tree: Enlarge Weight Limit, Discount, Overcharge, Pushcart, Item Appraisal,
     Vending, Mammonite.
4. **Blacksmith job change, Einbroch.**
   - Travel by a Geffen guildsman's warp, then the Izlude → Juno → Einbroch airships.
   - A written quiz (the scored answers are in the script, so they are L3 data).
   - A random item set to bring.
   - A delivery to a far town.
   - A second quiz.
   - The job change.

**Phase 3 data scope:** the species on the leveling candidates up to level 25. That is 56 maps and
115 species locally (the detector's class list is a separate decision), plus the town NPCs above
as the `npc` class.

## The operator HUD (PROPOSED, Batt 2026-10-08) — display-only, a console toggle
**Provenance:** ideas only. Batt shared a screen recording of another RO bot's debug view: its
origin, server and licence are unknown. No code, assets or screenshots were copied into the repo.

**What it shows**, over the stream. It is drawn on its own canvas like the route preview, and
carries no input (protocol), exactly as `route_preview`:

| element | content | source (ours) |
|---|---|---|
| detector boxes | class + confidence + distance in CELLS, not px (the Chebyshev distance from our cell to the cell under the box's feet) | the rule's detector frame; `poring_dataset.picking` + the camera model |
| the locked target | highlighted, with its lock countdown | the targeting rule (the proposals below) |
| the work zone | the game area minus the client's UI windows, outlined | `route_preview.UI_WINDOWS` (the same mask the clicks will use, walk@12) |
| the walk vector | the live route (RA2 style) + its destination cell as text | `route_preview` (built) |
| a short live log | the rule's decisions in plain words: "walking to (x,y)", "attacking", "detected …", "refused: TALK" | the rule's own records (demo log) |
| counters | units in view, the detector's rate (FPS) | the rule |

**Rules:**
- A per-tab toggle, off by default, like "Watch only".
- The messages are display-only and reach viewers only, never the mux (the
  `test_secret_input` pattern for `route_preview`).
- A new protocol message means `gen_protocol.sh` plus a backend restart (a market-closed window).
- **Distances in cells** come from our own camera model and picking, never screen px. The rules
  reason in cells.
